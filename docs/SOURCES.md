# Public-domain MusicXML sources — survey

Findings from a source audit where **every URL below was actually fetched**, not
assumed. Recorded so the in-app browse/download feature (SPEC §5) can be built
without repeating the investigation.

**Headline: a live search API is not feasible.** No service lets you query
"solo piano MusicXML" and receive files. The answer is a curated index shipped
with the app, pointing at commit-pinned CDN URLs.

## Rejected, with reasons

- **IMSLP** — 54,282 works in `Category:For piano` and a live MediaWiki API
  (verified 200), but file downloads redirect to an MTCaptcha bot check even
  with a browser UA and the disclaimer cookie. The sanctioned `API.ISCR.php`
  bulk route requires an IMSLP-granted account. **Use for metadata enrichment
  only** (opus numbers, dates, composer canonicalization) — never for files, and
  never work around the CAPTCHA.
- **MuseScore.com** — `robots.txt` explicitly contains `Disallow:
  /score/*/download/*` and `Disallow: /api/jmuse`. Do not scrape. The
  sanctioned route to the same OpenScore content is the CC0 GitHub mirror above.
- **PDMX** ([Zenodo](https://zenodo.org/records/15571083)) — real, CC-BY-4.0,
  and huge, but ships as monolithic archives (`mxl.tar.gz` = 1.89 GB) with no
  per-file URLs. Analysis of the 9,035-row sample: 70% are nominally solo piano,
  but the dominant artist is `Misc tunes` (folk fragments) and only ~0.9% match
  a canonical PD composer. Its own README admits copyright metadata
  discrepancies affecting 12.29% of songs. **Not worth 1.9 GB.**
- **Mutopia** — publishes `.ly`, `.mid`, `.pdf`, `.ps.gz`, `.svg`. **Zero
  MusicXML.** Eliminated.
- **Humdrum/KernScores corpora** (craigsapp) — ~340–400 solo-piano `.krn` files
  (Beethoven sonatas, Mozart sonatas, Chopin mazurkas, Scarlatti), but **no
  MusicXML**, and `kern.humdrum.org` is currently down (503). Would need
  offline `hum2xml` conversion.
- **DCMLab corpora** — alive and richly annotated, but MuseScore `.mscx` only.
- **CPDL** — 1,870 MusicXML files via a clean API, but choral SATB; effectively
  zero solo piano. (Note: 403s the default urllib UA; any custom UA works.)
- **Wikifonia** — defunct, domain now parked.

## Delivery notes (verified)

- **Use jsDelivr, not raw.githubusercontent**: `cdn.jsdelivr.net/gh/<owner>/<repo>@<sha>/<path>`
  returned byte-identical files with the correct
  `application/vnd.recordare.musicxml` MIME type, and is a real CDN. Pin to a
  **commit SHA** — `@main` can shift underneath you, SHA-pinned paths are cached
  immutably.
- **Never sniff format by extension.** All three exist in the wild: real zipped
  `.mxl` (Lieder, musetrainer), plain `.musicxml` (ASAP), and *uncompressed XML
  misnamed* `.mxl` (CPDL). Sniff the `PK` zip magic bytes instead.
- **Filter to solo piano by structure, not filename**: keep scores where
  `<score-part>` count is 1 and `<staves>` ≥ 2, or a part-name matches piano.
  This check is what reduced music21's 92 candidates to 14 real ones.
- Enumerate repos with `git clone --depth 1 --filter=blob:none --no-checkout`
  rather than the GitHub REST API (rate limits, and it indexes code not music).

## Planned index schema

Ship `assets/scores/index.json`, regenerated by a script in `tools/` and
committed (quarterly refresh — these corpora are near-static):

```json
{
  "schemaVersion": 1,
  "sources": { "asap": { "license": "CC-BY-NC-SA-4.0", "attribution": "…" } },
  "pieces": [{
    "id": "asap:beethoven/piano_sonatas/8-2",
    "title": "Piano Sonata No. 8 'Pathétique', Mvt. 2",
    "composer": "Beethoven, Ludwig van",
    "sourceId": "asap",
    "url": "https://cdn.jsdelivr.net/gh/fosfrancesco/asap-dataset@<sha>/…/xml_score.musicxml",
    "format": "musicxml",
    "bytes": 847435, "sha256": "…",
    "pianoPartId": "P1", "hasVoicePart": false, "staves": 2,
    "measures": 73, "noteCount": 2914,
    "keySignature": "Ab", "timeSignature": "2/4", "tempoBpm": 52,
    "difficulty": 6, "handSpanSemitones": 14
  }]
}
```

Difficulty and all structural fields are computed **offline** during index
generation, never on device — that is what lets browse/search feel instant and
lets the app auto-pick a next piece without a decision menu (SPEC §2).

Fetching on the user's behalf at runtime (rather than bundling) also sidesteps
redistribution entirely, which matters for ASAP's ShareAlike clause. Only the
CC0 Lieder files are safe to bundle in the APK.
